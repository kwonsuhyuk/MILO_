# MILO 디자인 시스템

## 문서 상태

- 상태: 방향 일부 확정, 세부 디자인 검토 중
- 목적: 프로젝트 생성 전에 브랜드와 UI의 공통 기준을 정한다.
- 원칙: 사용자가 디자인을 항목별로 검토하고 승인한 내용만 확정한다.

## 1. 브랜드 컨셉

### 차분한 성장 동반자

MILO는 취업 준비 과정의 불안을 자극하는 평가 도구가 아니라,
흩어진 기록을 연결하고 다음 행동을 차분하게 안내하는 개인 도구를 지향한다.

핵심 인상은 다음 다섯 가지다.

- 친근함: 처음 사용해도 부담이 없고 문장이 딱딱하지 않다.
- 신뢰감: 이력서와 지원 결과 같은 민감한 데이터를 안전하게 다룬다는 인상을 준다.
- 명료함: 현재 상태와 다음 할 일을 빠르게 파악할 수 있다.
- 연결성: 문서, 지원, 일정과 결과가 이어진다는 제품 차별점을 드러낸다.
- 응원: 결과를 단정하거나 압박하지 않고 사용자가 계속 기록할 수 있게 돕는다.

귀여움은 과도한 장식보다 둥근 형태, 짧고 따뜻한 문장,
작은 마이크로 일러스트와 부드러운 상호작용으로 표현한다.

## 2. 확정된 시각 방향

- 브랜드 중심 색상은 Milo Lime `#9DDF50`을 사용한다.
- 화면은 화이트 배경을 기본으로 한다.
- 브랜드 심볼은 MILO라는 이름과 어울리도록 미국 도로와 도로 표지판의 인상을 활용한다.
- MVP는 라이트 테마만 제공한다.
- 다크 모드는 MVP 이후 확장한다.
- 개별 화면 디자인은 사용자 확인 후 확정한다.

연한 연두색은 넓은 배경 전체보다 주요 버튼, 선택 상태, 브랜드 심볼과
강조 영역에 사용한다. 색이 밝아 흰색 글자와 충분한 대비가 나오지 않는 경우
어두운 전경색을 사용한다.

## 3. 색상 토큰 구조

첫 번째 `Milo Lime` 방향에서 화이트 배경과의 구분을 높인
`#9DDF50`을 브랜드 중심 색상으로 확정한다.

구현에서는 아래처럼 역할을 나타내는
의미 기반 토큰을 사용하고 컴포넌트에서 `lime-400` 같은 원시 색상을 직접 반복하지 않는다.

| 역할 | 토큰 | 현재 방향 |
| --- | --- | --- |
| 전체 배경 | `background` | 화이트 |
| 기본 글자 | `foreground` | 화이트 배경에서 읽기 쉬운 짙은 중립색 |
| 카드 | `card` | 화이트 또는 배경과 구분되는 매우 옅은 중립색 |
| 카드 글자 | `card-foreground` | 짙은 중립색 |
| 브랜드 | `primary` | Milo Lime `#9DDF50` |
| 브랜드 위 글자 | `primary-foreground` | 짙은 녹갈색 `#17210F` |
| 브랜드 경계 | `primary-border` | 짙은 연두 `#78B72F` |
| 보조 표면 | `secondary` | 연두와 조화를 이루는 옅은 중립색 |
| 약한 표면 | `muted` | 비활성·보조 영역용 옅은 중립색 |
| 보조 글자 | `muted-foreground` | WCAG AA 대비를 만족하는 중간 중립색 |
| 경계선 | `border` | 화이트 표면을 구분하는 옅은 중립색 |
| 포커스 | `ring` | 브랜드 계열이면서 배경과 구분되는 색 |
| 성공 | `success` | 브랜드 연두와 구별되는 진한 초록 계열 |
| 주의 | `warning` | 주황 또는 황갈색 계열 |
| 오류 | `destructive` | 빨강 계열 |
| 정보 | `info` | 파랑 계열 |

브랜드 색상과 합격·완료를 뜻하는 성공 색상은 같은 초록 계열이더라도
명도, 채도와 아이콘을 달리해 의미가 혼동되지 않게 한다.

## 4. 테마 구현 원칙

- Tailwind CSS와 shadcn/ui의 CSS 변수 방식을 사용한다.
- 클래스에는 `bg-primary`, `text-foreground`, `border-border`처럼 역할 기반 이름을 사용한다.
- 원시 색상 값은 전역 토큰 선언부에 모은다.
- MVP에서는 `:root` 라이트 토큰만 제품 품질로 완성한다.
- 추후 `.dark` 토큰을 추가할 수 있도록 컴포넌트는 테마에 종속된 원시 색상을 갖지 않는다.
- 차트 색상도 의미 기반 변수로 관리하고 같은 의미에는 같은 색상을 사용한다.

## 5. 로고 및 브랜드 아이콘

초기 로고는 Milo Lime 도로 방패 안에 굵은 `M`을 넣은 단순한 심볼을 사용한다.
작은 파비콘에서도 알아볼 수 있도록 장식과 세부 문구를 넣지 않는다.
초기 구현 이후 브랜드를 다듬을 때 형태와 워드마크를 교체할 수 있다.

- 원본: [`assets/milo-mark.svg`](assets/milo-mark.svg)
- 배경: Milo Lime `#9DDF50`
- 선과 글자: `#17210F`
- 형태: 미국 도로 방패를 단순화한 외곽과 하나의 `M`

향후 개선 시에도 미국 도로를 연상시키는 독자적인 형태를 유지한다.

- 방향 후보: 미국 고속도로 표지판 실루엣, 도로 방패 형태, 차선 또는 이어지는 경로
- 워드마크: `MILO`를 읽기 쉬운 형태로 유지한다.
- 심볼: 파비콘과 모바일 내비게이션에서도 식별 가능한 단순한 형태로 만든다.
- 색상: 연한 연두를 중심으로 하되 작은 크기에서도 충분한 대비를 확보한다.
- 연결성: 도로 또는 경로가 문서에서 지원 결과까지 이어지는 제품 경험을 상징하게 한다.
- 독창성: 실제 미국 도로 표지판을 그대로 복제하지 않고 MILO만의 비율과 형태로 재해석한다.
- 피할 표현: 흔한 서류가방 단독 심볼, 과도한 체크 표시, AI 서비스처럼 보이는 반짝이 남용

브랜드 심볼은 직접 제작하는 그래픽 자산이며 일반 UI 아이콘과 분리한다.

## 6. 일반 UI 아이콘

- 화면 안의 일반 기능 아이콘은 `lucide-react`를 사용한다.
- 기본 크기는 16px 또는 20px로 하고 한 화면에서 선 굵기를 일관되게 유지한다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.
- 핵심 행동은 아이콘만으로 표시하지 않고 가능하면 텍스트 레이블을 함께 쓴다.
- 합격, 불합격, 경고처럼 중요한 의미는 아이콘과 문구를 함께 표시한다.

제품 기능에는 다음 아이콘 계열을 우선 검토한다.

- 대시보드: `LayoutDashboard`
- 지원 기록: `BriefcaseBusiness`
- 이력서·자기소개서: `FileText`
- 문서 버전: `GitBranch`
- 일정: `CalendarDays`
- 관계 보기: `Network`
- 통계: `ChartNoAxesCombined`
- 보안: `ShieldCheck`

## 7. 타이포그래피 후보

- 한국어 기본 서체 후보: Pretendard Variable
- 대체 서체: `system-ui`, `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `sans-serif`
- 숫자와 통계: 동일한 글꼴에서 tabular numbers 사용
- 본문 기본 크기 후보: 16px
- 보조 문구 최소 크기: 12px, 핵심 정보는 14px 이상
- 본문 줄 높이 후보: 약 1.5~1.65
- 굵기는 400, 500, 600을 중심으로 사용한다.

서체와 구체적인 크기 체계는 사용자 검토 후 확정한다.

## 8. 형태와 공간 후보

- 간격 단위: 4px 기반
- 기본 화면 여백 후보: 모바일 16px, 데스크톱 24~32px
- 모바일 주요 조작 영역은 최소 44×44px 확보
- 그림자는 떠 있는 메뉴와 모달에 제한하고 일반 카드는 경계선으로 구분
- 한 화면에 카드가 지나치게 많아지지 않도록 표, 목록과 구획선을 함께 활용

모서리 크기, 버튼 높이, 카드 밀도와 그림자 단계는 화면 시안 검토 후 확정한다.

## 9. 상태와 데이터 표현

- 진행 중: 브랜드 또는 정보 색상 + 진행 아이콘 + 상태명
- 합격·완료: 성공 색상 + 체크 아이콘 + 상태명
- 불합격: 오류 색상 + 명확한 상태명
- 응답 없음: 중립 또는 주의 색상 + 시간 아이콘 + 상태명
- 지원 철회·채용 취소: 중립 색상 + 종료 사유
- 기한 초과: 오류 색상을 제한적으로 사용하고 다음 행동을 함께 제시

차트는 장식용 색상을 늘리지 않고 같은 의미에는 같은 색상을 사용한다.
통계 카드에는 수치만 보여주지 않고 계산 대상과 표본 수를 함께 표시한다.

## 10. 접근성 및 반응형 원칙

- 일반 텍스트와 배경은 WCAG AA 수준의 대비를 목표로 한다.
- 키보드 포커스를 항상 확인할 수 있게 한다.
- 색상만으로 상태나 선택 여부를 전달하지 않는다.
- 모바일과 데스크톱에서 동일한 핵심 작업을 완료할 수 있어야 한다.
- 터치 조작 영역은 가능한 한 44×44px 이상 확보한다.
- 움직임 감소 설정을 존중하고 불필요한 반복 애니메이션을 사용하지 않는다.
- 오류는 발생 위치, 원인과 해결 방법을 함께 안내한다.
