# MILO (마일로) — MVP 제품 요구사항 문서

- 문서 상태: 초안
- 버전: 0.1
- 작성일: 2026-10-16
- 기준 문서: `docs/PROJECT_CONTEXT.md`, `docs/DECISIONS.md`

## 1. 문서 목적

이 문서는 MILO 첫 출시에서 제공할 사용자 경험, 기능 범위와 완료 조건을 정의한다.
기술 스택과 구체적인 구현 방식은 아키텍처 문서에서 별도로 결정한다.

## 2. 제품 요약

MILO는 취업 또는 이직을 준비하는 사용자가 이력서와 자기소개서의 여러 버전,
기업 지원 기록, 전형 결과와 일정을 연결해 관리하고 분석하는 웹서비스다.

핵심 가치는 단순 파일 보관이 아니라 다음 질문에 답할 수 있게 하는 것이다.

- 어떤 기업과 직무에 지원했는가?
- 그때 어떤 이력서와 자기소개서 버전을 제출했는가?
- 전형은 어디까지 진행됐고 결과는 어땠는가?
- 지금 가장 먼저 해야 할 일은 무엇인가?
- 누적된 지원 기록에서 어떤 경향을 확인할 수 있는가?

## 3. 해결하려는 문제

- 기업마다 다르게 제출한 이력서와 자기소개서의 버전이 흩어진다.
- 어떤 지원에 어떤 문서를 제출했는지 시간이 지나면 확인하기 어렵다.
- 전형 상태, 일정, 메모와 결과를 일관되게 관리하기 어렵다.
- 지원 결과가 누적되어도 합격률, 단계 전환율과 미응답률을 직접 계산해야 한다.
- 범용 문서 도구는 사용자가 데이터 구조와 관계를 직접 구성해야 한다.

## 4. 대상 사용자

### 핵심 사용자

직무와 경력에 관계없이 취업 또는 이직을 준비하며 여러 제출 문서와 기업 지원 내역을
관리하려는 사람이다.

### 초기 사용자 후보

개발자 취업 준비생을 초기 사용자군 중 하나로 고려하되 서비스 기능은 특정 직무에
종속되지 않게 설계한다. 신입과 경력직 모두 사용할 수 있어야 한다.

## 5. MVP 목표

1. 사용자가 문서 없이도 첫 지원 기록을 빠르게 생성할 수 있게 한다.
2. 이력서와 자기소개서를 문서와 버전 단위로 관리할 수 있게 한다.
3. 실제 제출한 문서 버전을 지원 기록과 연결할 수 있게 한다.
4. 전형 상태, 결과, 변경 이력과 다음 일정을 한곳에서 확인할 수 있게 한다.
5. 확정 합격률, 전체 지원 기준 단계 전환율과 미응답률을 자동 계산한다.
6. 원본 파일과 개인 지원 기록을 기본 비공개로 안전하게 관리한다.

## 6. MVP 비목표

다음 기능은 제품 방향에 포함되지만 첫 출시에서는 구현하지 않는다.

- Gmail 및 Outlook 연동과 전형 상태 자동 반영
- 통계와 제출 문서별 결과를 해석하는 AI 취업 활동 인사이트
- AI 기업·채용공고 분석과 면접 준비 자료 생성
- 커뮤니티, 이력서 공개, 피드백과 첨삭
- 전체 관계 그래프
- PDF 텍스트 자동 추출, OCR, Git 스타일 자동 비교와 AI 변경 요약
- 자기소개서 직접 작성과 문항별 답변 재사용
- 외부 캘린더 연동과 이메일·푸시 알림
- DOCX 및 HWP/HWPX 문서 지원
- 지원 기록 CSV 및 전체 데이터 내보내기
- 관심 공고 저장과 지원 전 공고 관리

## 7. 핵심 사용자 흐름

### 7.1 빠른 지원 기록

1. 사용자가 로그인한다.
2. 기업명과 지원 직무를 입력한다. 지원 날짜는 오늘로 자동 입력되며 필요하면 수정한다.
3. 시스템이 현재 단계를 `서류`, 전체 결과를 `진행 중`으로 설정하고 `지원 완료` 최초 이벤트를 생성한다.
4. 사용자는 필요할 때 채용공고, 제출 문서, 일정과 상세 정보를 추가한다.

### 7.2 제출 문서 등록

1. 사용자가 PDF 파일을 선택한다.
2. 새 문서 또는 기존 문서의 새 버전으로 등록한다.
3. 문서 종류와 이름을 입력하고 필요하면 버전 별칭과 변경 내용을 추가한다.
4. 등록된 버전을 하나 이상의 지원 기록에 연결한다.

### 7.3 전형 진행

1. 사용자가 현재 단계와 결과를 변경한다.
2. 시스템이 이전 값, 변경 값, 시각과 변경 주체를 이력에 추가한다.
3. 사용자가 테스트, 과제, 면접 또는 후속 연락 일정을 추가한다.
4. 대시보드가 가장 가까운 미완료 항목을 다음 할 일로 보여준다.

### 7.4 결과 확인

1. 사용자가 대시보드에서 진행 중인 지원과 예정 일정을 확인한다.
2. 결과가 누적되면 확정 합격률, 전체 지원 전환율과 미응답률을 확인한다.
3. 특정 지원에서 제출 문서 버전과 전체 전형 이력을 다시 확인한다.

- 지원 이유
- 메모
- 일정과 다음 할 일

## 9. 기능 요구사항

우선순위는 `Must`가 MVP 출시 필수, `Should`가 출시 전 포함을 목표로 하지만 핵심 흐름을
막지 않는 항목을 의미한다.

### 9.1 계정

| ID | 우선순위 | 요구사항 | 완료 조건 |
| --- | --- | --- | --- |
| AUTH-001 | Must | 사용자는 Google 또는 Kakao 계정으로 가입하고 로그인·로그아웃할 수 있다. | 두 제공자의 OAuth 로그인이 동작하고, 인증되지 않은 사용자는 개인 데이터 화면에 접근할 수 없으며 로그인한 사용자는 자신의 데이터만 조회한다. |
| AUTH-002 | Must | 사용자는 계정을 탈퇴할 수 있다. | 탈퇴 범위와 복구 불가 여부를 안내하고 확인 후 개인 데이터 삭제 절차를 시작한다. |

이메일·비밀번호와 매직 링크 로그인은 제공하지 않는다. Naver 로그인은 MVP 이후에
Custom OAuth 호환성을 검증한 뒤 추가한다. 소셜 로그인 권한과 Gmail 채용 메일 분석
권한은 분리해 요청한다.

### 9.2 문서와 버전

| ID | 우선순위 | 요구사항 | 완료 조건 |
| --- | --- | --- | --- |
| DOC-001 | Must | 사용자는 이력서, 자기소개서 또는 통합 문서를 만들 수 있다. | 문서 종류와 사용자가 입력한 문서명을 저장하고 사용자 본인만 조회할 수 있다. |
| DOC-002 | Must | 사용자는 새 파일을 새 문서 또는 기존 문서의 새 버전으로 등록할 수 있다. | 업로드 흐름에서 두 선택지가 구분되고 선택한 문서 아래에 버전이 생성된다. |
| DOC-003 | Must | MVP는 PDF 파일만 허용한다. | 실제 PDF 형식이며 10MB 이하이고 암호화되지 않은 파일만 저장된다. 실패 시 원인을 안내한다. |
| DOC-004 | Must | 각 버전은 자동 증가하는 버전 번호와 등록 시각을 가진다. | 같은 문서 안에서 `v1`, `v2`, `v3` 순서로 생성되며 버전 번호는 사용자가 수정할 수 없다. |
| DOC-005 | Should | 사용자는 버전 별칭과 변경 내용을 선택적으로 입력할 수 있다. | 비워도 업로드할 수 있고 입력한 경우 버전 목록과 상세 화면에 표시된다. |
| DOC-006 | Must | 시스템은 업로드한 원본 파일명을 보존한다. | 버전 상세에서 원본 파일명을 확인할 수 있다. |
| DOC-007 | Must | 제출 기록에 연결된 버전은 덮어쓰지 않는다. | 파일 교체가 필요하면 새 버전이 생성되고 기존 연결은 유지된다. |
| DOC-008 | Should | 사용자는 같은 문서의 두 PDF 버전을 나란히 볼 수 있다. | 두 버전을 선택하면 각 PDF를 구분해 조회할 수 있다. |
| DOC-009 | Must | 사용자는 원본 파일만 삭제할 수 있다. | 원본, 미리보기와 파생 데이터가 삭제되고 지원 이력에는 최소 메타데이터만 남는다. |
| DOC-010 | Must | 사용자는 버전 전체를 삭제할 수 있다. | 삭제 결과를 안내하고 확인 후 파일과 버전 정보를 삭제하며 지원 기록의 문서 연결을 해제한다. |
| DOC-011 | Should | 사용자는 사용하지 않는 문서를 보관 처리할 수 있다. | 보관된 문서는 기본 목록에서 숨겨지며 영구 삭제와 구분된다. |

### 9.3 지원 기록

| ID | 우선순위 | 요구사항 | 완료 조건 |
| --- | --- | --- | --- |
| APP-001 | Must | 사용자는 제출 문서 없이 지원 기록을 생성할 수 있다. | 기업명, 지원 직무와 지원 날짜만으로 저장된다. |
| APP-002 | Must | 새 지원 기록은 기본 상태와 최초 이벤트를 가진다. | 현재 단계 `서류`, 전체 결과 `진행 중`으로 저장되고 `지원 완료` 이벤트가 생성되며 화면에도 `지원 완료`로 표시된다. |
| APP-003 | Must | 사용자는 선택 상세 정보를 입력하고 수정할 수 있다. | 공고 URL, 지원 경로와 플랫폼명, 채용 형태, 근무 형태와 지역, 공고 내용, 강조점, 지원 이유와 메모를 저장할 수 있다. |
| APP-004 | Must | 사용자는 이력서·자기소개서 버전을 지원 기록에 연결하거나 해제할 수 있다. | 문서 없이도 기록이 유지되며 연결 시 정확한 버전이 표시된다. |
| APP-005 | Must | 사용자는 현재 단계와 전체 결과를 변경할 수 있다. | 현재 단계는 `서류`, `테스트/과제`, `면접`, `처우 협의` 중 하나다. |
| APP-006 | Must | 종료된 지원은 종료 사유를 가진다. | 종료 사유는 `지원 철회`, `응답 없음`, `채용 취소`, `기타` 중 하나이며 당시 단계를 보존한다. |
| APP-007 | Must | 사용자는 응답 없음으로 종료한 지원을 다시 열 수 있다. | 전체 결과를 진행 중으로 변경하고 새 변경 이력을 추가한다. |
| APP-008 | Must | 전형 변화는 단계 진입, 단계 합격, 단계 불합격, 지원 종료와 지원 재개 이벤트로 기록된다. | 이벤트 종류, 대상 단계, 발생 시각, 이전 값, 변경 값과 변경 주체가 저장되고 타임라인에서 확인된다. |
| APP-009 | Must | 일정 완료와 전형 결과를 별도로 관리한다. | 테스트나 면접 일정을 완료해도 합격·불합격 결과가 자동 생성되지 않는다. |
| APP-010 | Must | 사용자는 여러 면접 기록에 세부 이름을 붙일 수 있다. | 현재 단계는 `면접`으로 유지하면서 `1차 직무 면접`, `컬처핏 면접` 등의 이름과 각각의 결과를 기록할 수 있다. |
| APP-011 | Must | 사용자는 상태 변경을 되돌릴 수 있다. | 이전 상태가 복원되며 되돌리기도 새로운 이벤트로 남는다. |
| APP-012 | Should | 30일 동안 새 활동이 없는 진행 중 지원에 응답 없음 종료를 제안한다. | 자동 종료하지 않고 사용자가 확인한 경우에만 상태를 변경한다. |
| APP-013 | Must | 사용자는 지원 기록을 삭제할 수 있다. | 삭제 범위를 안내하고 확인 후 지원 정보, 일정과 관련 이력을 삭제한다. 연결된 원본 문서 자체는 별도 삭제 전까지 유지한다. |

| ID | 우선순위 | 요구사항 | 완료 조건 |
| --- | --- | --- | --- |

| TASK-003 | Must | 가장 가까운 미완료 항목을 다음 할 일로 표시한다. | 지원 상세와 대시보드에서 동일한 항목이 표시된다. |
| TASK-004 | Must | 사용자는 할 일을 완료 처리할 수 있다. | 완료 항목은 다음 할 일 후보에서 제외되고 완료 상태가 유지된다. |
| TASK-005 | Must | 기한이 지난 미완료 항목을 구분한다. | 시간이 있는 일정은 해당 시각 이후, 날짜만 있는 일정은 저장된 시간대에서 해당 날짜가 끝난 이후 기한 초과로 표시된다. |

| STAT-002 | Must | 진행 중인 지원 건수를 보여준다. | 전체 결과가 `진행 중`인 지원만 집계한다. |
| STAT-003 | Must | 현재 단계별 지원 건수를 보여준다. | 서류, 테스트/과제, 면접과 처우 협의 단계의 진행 중 지원을 각각 집계한다. |

| STAT-008 | Must | 모든 비율에 실제 건수를 함께 보여준다. | 퍼센트와 분자·분모 또는 해당 건수를 같은 화면에서 확인할 수 있다. |
| STAT-009 | Must | 분모가 0인 통계를 안전하게 표시한다. | `0%`나 숫자 오류 대신 계산할 결과가 없다는 안내를 표시한다. |
| STAT-010 | Should | 문서 버전별 지원 결과를 보여준다. | 특정 버전에 연결된 지원 수와 결과를 확인할 수 있고 인과관계로 단정하는 표현을 사용하지 않는다. |
| STAT-011 | Should | 기간별 지원 추이를 보여준다. | 사용자가 선택한 기간의 지원 건수 변화를 확인할 수 있다. |

## 11. 데이터 및 개인정보 요구사항

- 원본 이력서, 자기소개서와 지원 기록은 기본 비공개다.
- 모든 개인 데이터 조회와 변경에서 사용자 소유권을 확인한다.
- MVP에는 다른 사용자에게 개인 데이터를 공유하는 기능이 없으며 소유자만 접근한다.
- 후속 공유 기능은 사용자가 선택한 자원과 권한 범위에만 적용하고 언제든 철회할 수 있어야 한다.
- 문서 공유 권한이 기업 지원 기록, 결과, 통계와 메모 접근 권한을 포함하지 않는다.
- 파일은 공개 주소가 아닌 짧은 유효기간의 접근 방식으로 제공한다.
- 파일 확장자가 아니라 실제 PDF 형식과 크기를 검사한다.
- 파일 내용이나 영구 접근 주소를 애플리케이션 로그에 남기지 않는다.
- 계정 탈퇴 시 파일, 파생 데이터, 지원 기록, 일정, 메모와 관계 데이터를 삭제한다.
- 법령상 별도 보관 의무가 있는 데이터가 생기면 다른 개인정보와 분리한다.
- AI 분석과 이메일 연동은 MVP에서 개인정보 처리 대상이 아니다.

## 12. 비기능 요구사항

### 접근성과 반응형 UI

- 모바일과 데스크톱에서 핵심 흐름을 완료할 수 있어야 한다.
- 폼 입력 항목은 연결된 레이블, 오류 설명과 키보드 조작을 지원해야 한다.
- 상태를 색상만으로 구분하지 않는다.
- PDF 비교가 어려운 작은 화면에서는 개별 문서를 전환해 볼 수 있는 대안을 제공한다.

### 유지보수성과 신뢰성

- TypeScript strict 모드를 사용한다.
- 서버 상태와 클라이언트 상태를 구분한다.
- 통계 계산은 화면마다 중복 구현하지 않고 동일한 규칙을 사용한다.
- 상태 변경과 현재 상태가 불일치하지 않도록 원자적으로 처리한다.
- 네트워크 또는 업로드 실패 시 사용자가 재시도할 수 있고 중복 데이터가 생성되지 않아야 한다.

### 성능

- 파일 업로드와 처리 중 진행 상태를 표시한다.
- 대시보드와 목록은 데이터가 증가해도 페이지네이션 또는 점진적 로딩으로 확장할 수 있어야 한다.
- 구체적인 성능 목표치는 기술 스택과 초기 사용자 규모를 정한 뒤 확정한다.

## 13. MVP 출시 기준

- 모든 `Must` 요구사항의 완료 조건을 충족한다.
- 회원가입부터 지원 등록, 문서 연결, 상태 변경, 일정 등록과 통계 확인까지 핵심 흐름을 실제 환경에서 완료할 수 있다.
- 다른 사용자의 문서와 지원 기록에 접근할 수 없음을 권한 테스트로 확인한다.
- PDF 형식, 크기와 암호화 파일 검증이 동작한다.
- 문서, 버전, 지원 기록과 계정 삭제 범위가 요구사항과 일치한다.
- 상태 변경 및 되돌리기 후 타임라인과 현재 상태가 일치한다.
- 합격률, 단계 전환율과 미응답률의 경계 조건을 테스트한다.
- 모바일과 데스크톱에서 핵심 흐름을 확인한다.
- 개인정보처리방침과 이용자 안내에 필요한 데이터 항목 및 보관·삭제 정책을 검토한다.

## 14. 출시 후 검증할 제품 가설

아래 항목은 확정된 성과가 아니라 출시 후 검증할 가설이다.

- 사용자는 범용 문서 도구보다 더 적은 설정으로 첫 지원 기록을 만들 수 있다.
- 사용자는 제출 문서 버전을 지원 기록과 연결하는 기능에서 가치를 느낀다.
- 다음 할 일과 일정이 반복적인 서비스 재방문에 도움이 된다.
- 문서 버전별 결과와 단계 통계가 다음 지원을 준비하는 데 도움이 된다.

구체적인 사용자 수, 재방문율과 유지율 목표는 베타 모집 계획과 분석 도구를 정한 뒤 확정한다.
