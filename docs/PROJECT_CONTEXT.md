# MILO (마일로) — 프로젝트 컨텍스트

## 1. 프로젝트 개요

- 서비스명: MILO (마일로)
- 서비스 형태: 웹서비스
- 대상: 취업 준비생, 신입 개발자, 이직 준비자
- 목표: 실제 사용자를 확보하고 장기적으로 운영하는 서비스

MILO는 취업 준비 과정에서 발생하는 이력서 관리,
기업 지원, 결과 분석, 정보 공유를 통합하는 플랫폼이다.

단순한 AI 이력서 생성기가 아니라,
사용자가 취업 준비 과정을 기록하고
데이터를 기반으로 개선할 수 있도록 돕는 서비스다.

## 2. 서비스 기획 배경

기획자는 실제 취업 준비 과정에서 다음 문제를 경험했다.

- 기업마다 다른 이력서를 제출하면서 버전 관리가 어려움
- 어떤 기업에 어떤 이력서를 제출했는지 추적하기 어려움
- 지원 결과를 기록하고 합격률을 비교하기 어려움
- 기업별 채용공고와 요구 역량을 분석하는 데 시간이 필요함
- 다른 취업 준비생의 이력서와 포트폴리오를 참고하고 싶음

이러한 문제를 하나의 웹서비스에서 해결하려 한다.

## 3. 제품 방향과 핵심 원칙

### 개인 사용자에게 먼저 가치 제공

초기 커뮤니티 사용자가 없어도 혼자서 충분히 활용할 수 있어야 한다.

### 웹서비스 우선

앱스토어 등록과 유지 비용을 피하고,
URL만으로 접근할 수 있는 반응형 웹서비스를 우선 개발한다.

필요하면 추후 PWA 또는 앱으로 확장한다.

### 초기 운영비 최소화

무료 호스팅과 데이터베이스 요금제를 우선 검토한다.

AI API 사용량과 파일 저장 비용을 제한해야 한다.

### 공유 가능한 개인 데이터

사용자의 취업 활동 기록과 통계를 시각화한다.

사용자가 원하는 일부 통계를 SNS에 공유할 수 있도록
추후 확장할 수 있다.

단, 기업 지원 내역과 개인정보는 기본 비공개다.

## 4. 핵심 기능

### A. 이력서 및 포트폴리오 버전 관리

- PDF 이력서 업로드
- 이력서별 버전 생성
- 버전명과 변경 사항 기록
- 이전 버전 조회
- 버전 간 내용 비교
- 포트폴리오 링크 관리
- 기업 지원 기록과 사용한 이력서 버전 연결

핵심은 단순 파일 저장이 아니라
어떤 버전을 어떤 기업에 제출했는지 추적하는 것이다.

### B. 기업 지원 현황 관리

- 지원 기업 등록
- 지원 직무 등록
- 채용공고 URL 저장
- 지원 날짜 기록
- 지원 당시 사용한 이력서 선택
- 현재 채용 전형 상태 관리
- 서류, 코딩테스트, 과제, 면접 결과 기록
- 기업별 메모 및 일정 관리

지원이 완료되면 해당 시점에 사용한 이력서 버전을 보존한다.

### C. 취업 활동 분석

- 총 지원 건수
- 진행 중인 지원 건수
- 서류 합격률
- 면접 합격률
- 이력서 버전별 지원 결과
- 기간별 지원 추이
- 기업 유형별 지원 결과

합격률 계산 시 진행 중인 지원은
확정 결과의 분모에 포함하지 않는다.

서로 다른 기업이나 직무에 지원한 결과를 비교할 때
이력서 변경만이 성과 차이를 만들었다고 단정하지 않는다.

### D. AI 기업 및 채용공고 분석

- 채용공고 텍스트 분석
- 필수 역량 및 우대사항 추출
- 사용자 이력서와 요구사항 비교
- 경험과 역량의 연결점 분석
- 이력서 보완 방향 제안
- 예상 면접 질문 생성
- 기업 분석 및 출처 표시

근거 없는 합격 확률을 생성하지 않는다.

AI 분석은 실제 채용공고와 확인 가능한 기업 정보를
기반으로 수행해야 한다.

### E. 취업 준비생 커뮤니티

- 익명 이력서 공유
- 이력서 피드백
- 포트폴리오 공유
- 취업 경험 공유
- 직군별 게시판
- 댓글 및 피드백

커뮤니티는 초기 MVP 이후에 구현한다.

사용자의 원본 이력서와 지원 기록은 기본 비공개다.

## 5. MVP 범위

첫 번째 출시에서 구현할 핵심 기능은 다음과 같다.

1. 회원가입 및 로그인
2. PDF 이력서 업로드
3. 이력서 버전 관리
4. 기업 및 지원 기록 등록
5. 채용 전형 상태 관리
6. 이력서 버전과 지원 기록 연결
7. 지원 현황 대시보드
8. 기본 합격률 통계

AI 기업 분석과 커뮤니티는 후속 단계에서 개발한다.

MVP 범위는 초기 제안이며 개발 전 최종 확정한다.

## 6. 사용자 흐름

1. 사용자가 회원가입한다.
2. 기존 이력서 PDF를 업로드한다.
3. 이력서 버전을 등록한다.
4. 지원할 기업과 채용공고를 등록한다.
5. 지원 당시 사용한 이력서 버전을 선택한다.
6. 채용 절차가 진행되면 상태를 변경한다.
7. 결과가 누적되면 대시보드에서 통계를 확인한다.
8. 추후 AI 분석과 커뮤니티를 이용한다.

## 7. 디자인 방향

- 친근하고 귀여운 브랜드 이미지
- 깔끔하고 직관적인 UI
- 토스처럼 이해하기 쉬운 사용자 경험 지향
- 모바일과 데스크톱 모두 대응
- 대시보드와 기록 관리에 최적화
- 불필요하게 복잡한 입력 과정 최소화

브랜드명은 MILO로 확정했다.

색상, 로고, 마스코트, 디자인 시스템은 미정이다.

## 8. 기술 스택 후보

- Next.js
- TypeScript (strict)
- Tailwind CSS
- shadcn/ui
- TanStack Query
- Zustand
- PostgreSQL
- Drizzle ORM
- Supabase Auth / Storage
- Recharts

기술 스택은 아직 최종 확정하지 않았다.

실제 요구사항에 맞춰 선택한다.

## 9. 초기 사용자 확보 전략

- 개발자 취업 준비생을 초기 대상으로 고려한다.
- 기존 이력서 PDF를 바로 등록할 수 있게 한다.
- 복잡한 초기 설정 없이 지원 내역을 기록할 수 있게 한다.
- 사용자 피드백을 받아 기능을 개선한다.
- 커뮤니티는 개인 기능에 사용자가 확보된 후 확장한다.

국내 참고 서비스:

- 자소설닷컴
- 링커리어
- 원티드
- 잡코리아

해외 참고 서비스:

- Huntr
- Teal

차별화하려는 핵심 경험:

1. 기업에 제출한 이력서 버전 추적
2. 이력서 버전과 지원 결과의 연결
3. 개인별 취업 활동 통계
4. 한국 취업 전형에 맞는 지원 관리
5. 익명 이력서 피드백 커뮤니티

위 차별점은 제품 가설이며
실제 시장에서 검증된 경쟁 우위는 아니다.

## 11. 아직 결정하지 않은 사항

- 최종 기술 스택
- 인증 방식
- 데이터베이스 스키마
- 이력서 버전 비교 방식
- PDF 저장 및 보관 정책
- AI 모델과 분석 비용
- 커뮤니티 운영 정책
- 서비스 로고와 브랜드 색상
- 구체적인 화면 구성
- 운영 환경과 배포 전략

이 항목들은 확정된 요구사항으로 취급하지 않는다.

## 12. 개발 목표

첫 번째 목표는 기능이 많은 서비스를 만드는 것이 아니다.

사용자가 실제로 이력서를 등록하고,
기업별 지원 내역을 기록하며,
그 기록을 다시 확인하고 싶어지는
작동 가능한 웹서비스를 출시하는 것이다.
