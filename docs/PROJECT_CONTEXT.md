# MILO (마일로) — 프로젝트 컨텍스트

## 1. 프로젝트 개요

- 서비스명: MILO (마일로)
- 서비스 형태: 웹서비스
- 대상: 직무와 경력에 관계없이 취업 또는 이직을 준비하며 이력서와 지원 내역을 관리하려는 사람
- 목표: 실제 사용자를 확보하고 장기적으로 운영하는 서비스

MILO는 취업 준비 과정에서 발생하는 이력서 관리,
기업 지원, 결과 분석, 정보 공유를 통합하는 플랫폼이다.

단순한 AI 이력서 생성기가 아니라,
사용자가 취업 준비 과정을 기록하고
데이터를 기반으로 개선할 수 있도록 돕는 서비스다.

### 사용자 범위

- MVP 핵심 사용자: 취업 또는 이직을 준비하며 여러 이력서·자기소개서 버전과 기업 지원 내역을 관리하려는 사람
- 초기 사용자 후보: 개발자 취업 준비생을 포함하되, 핵심 기능은 특정 직무에 종속되지 않게 설계한다.
- 확장 사용자: 다른 사람의 이력서를 참고하거나 피드백을 받고 싶은 사용자
- 커뮤니티 기여자: 실무 경험이나 취업 경험을 바탕으로 다른 사용자의 이력서를 첨삭하고 피드백할 수 있는 경력자

신입과 경력직 모두 서비스 대상이며, 직군별 차이가 필요한 기능은 실제 사용자 검증 후 확장한다.

## 2. 서비스 기획 배경

기획자는 실제 취업 준비 과정에서 다음 문제를 경험했다.

- 기업마다 다른 이력서를 제출하면서 버전 관리가 어려움
- 어떤 기업에 어떤 이력서를 제출했는지 추적하기 어려움
- 지원 결과를 기록하고 합격률을 비교하기 어려움
- 기업별 채용공고와 요구 역량을 분석하는 데 시간이 필요함
- 다른 취업 준비생의 이력서와 포트폴리오를 참고하고 싶음

이러한 문제를 하나의 웹서비스에서 해결하려 한다.

## 3. 제품 방향과 핵심 원칙

### 개인 사용자에게 먼저 가치 제공

초기 커뮤니티 사용자가 없어도 혼자서 충분히 활용할 수 있어야 한다.

### 웹서비스 우선

앱스토어 등록과 유지 비용을 피하고,
URL만으로 접근할 수 있는 반응형 웹서비스를 우선 개발한다.

필요하면 추후 PWA 또는 앱으로 확장한다.

### 초기 운영비 최소화

무료 호스팅과 데이터베이스 요금제를 우선 검토한다.

AI API 사용량과 파일 저장 비용을 제한해야 한다.

### 공유 가능한 개인 데이터

사용자의 취업 활동 기록과 통계를 시각화한다.

사용자가 원하는 일부 통계를 SNS에 공유할 수 있도록
추후 확장할 수 있다.

단, 기업 지원 내역과 개인정보는 기본 비공개다.

개인 데이터 접근 권한은 기본적으로 소유자에게만 있다.
후속 공유 기능에서 사용자가 특정 문서나 통계를 명시적으로 허용한 경우에만
해당 범위에 한해 다른 사용자가 접근할 수 있다. 공유 허용은 언제든 철회할 수 있어야 하며,
이력서 공유가 기업 지원 내역, 결과, 메모와 다른 개인정보 공개로 이어져서는 안 된다.

### 연결 중심의 취업 데이터

MILO는 노션 취업 관리 템플릿처럼 지원 현황을 한곳에서 관리하는 편리함을 제공하되,
사용자가 데이터베이스를 직접 설계하거나 관계를 설정하지 않아도 바로 사용할 수 있어야 한다.

이력서, 자기소개서, 기업, 지원 기록, 전형 단계와 결과 사이의 관계를 자동으로 연결한다.
축적된 관계는 옵시디언의 그래프 뷰처럼 시각적으로 탐색할 수 있도록 확장한다.
시각화는 장식이 아니라 어떤 문서를 어디에 제출했고 어떤 결과로 이어졌는지 이해하는 수단이어야 한다.

## 4. 핵심 기능

### A. 이력서, 자기소개서 및 포트폴리오 관리

- PDF 이력서 업로드
- MVP 제출 문서는 PDF만 지원
- 파일당 최대 크기는 10MB
- 암호화된 PDF는 업로드 제한 및 해제 방법 안내
- 목적이 다른 이력서를 각각 독립된 문서로 생성
- 각 이력서 문서 안에서 버전 생성
- 버전명과 변경 사항 기록
- 이전 버전 조회
- 선택한 두 PDF 버전을 나란히 비교
- 자기소개서를 이력서와 별도로 생성하고 관리
- 이력서와 자기소개서를 함께 묶은 문서도 관리
- 자기소개서별 버전과 제출 내역 관리
- 포트폴리오 링크 관리
- 기업 지원 기록과 사용한 이력서·자기소개서 버전 연결

핵심은 단순 파일 저장이 아니라
어떤 이력서와 자기소개서 버전을 어떤 기업에 제출했는지 추적하는 것이다.

이력서와 자기소개서는 각각 독립적으로 관리할 수 있어야 한다.
사용자가 두 문서를 하나의 파일로 관리하는 경우도 지원할 수 있어야 한다.

새 파일을 등록할 때 `새 문서로 등록` 또는 `기존 문서의 새 버전` 중 하나를 선택한다.
같은 목적과 구성을 수정한 파일은 기존 문서의 새 버전으로,
목표 직무나 강조 방향이 다른 파일은 새로운 문서로 관리할 수 있다.
구분은 서비스가 강제하지 않고 사용자가 결정한다.

지원 기록은 문서가 아니라 실제로 제출한 특정 버전에 연결한다.
제출 기록에 연결된 버전은 수정하거나 덮어쓰지 않는다.

#### 문서 보관 및 삭제 원칙

- 이력서와 자기소개서 원본은 기본 비공개로 보관한다.
- 제출된 버전은 덮어쓰지 않지만 사용자는 언제든 삭제할 수 있다.
- 원본 파일만 삭제하면 PDF, 미리보기, 추출 텍스트 및 해당 파일에서 생성한 AI 분석 데이터를 삭제한다.
- 원본 파일만 삭제한 경우 지원 이력에 필요한 문서명, 버전명, 제출 날짜 등 최소 메타데이터는 유지할 수 있다.
- 버전 전체를 삭제하면 지원 기록에서 해당 문서 연결을 해제하되 기업, 지원 날짜, 상태와 결과는 유지한다.
- 사용자가 지원 기록까지 삭제하면 연결된 기록과 관련 메타데이터를 함께 삭제한다.
- 보관은 목록에서 숨기는 기능이며 영구 삭제와 명확히 구분한다.
- 계정 탈퇴 시 원본 파일, 파생 데이터, 지원 기록, 메모, 메일 연동 정보 및 관계 데이터를 삭제한다.

파일은 사용자별 접근 권한을 검사하는 비공개 저장소에 보관하고,
외부에 영구 공개되는 파일 주소를 제공하지 않는다.
파일 접근 링크는 짧은 유효기간을 사용하고 접근 기록을 남긴다.
업로드 시 확장자뿐 아니라 실제 PDF 형식과 파일 크기를 검사한다.

### B. 기업 지원 현황 관리

- 지원 기업 등록
- 지원 직무 등록
- 채용공고 URL 저장
- 지원 날짜 기록
- 지원 당시 사용한 이력서·자기소개서 버전 선택(선택 사항)
- 현재 채용 전형 상태 관리(필수, 기본값 제공)
- 서류, 코딩테스트, 과제, 면접 결과 기록
- 기업별 메모 및 여러 일정 관리
- 가장 가까운 미완료 일정을 다음 할 일로 표시

이력서나 자기소개서가 없어도 지원 기록을 먼저 생성할 수 있다.
제출 문서는 지원 기록을 생성할 때 연결하지 않아도 되며 나중에 추가할 수 있다.
지원이 완료되면 해당 시점에 사용한 문서 버전을 보존한다.
현재 지원 상태는 통계와 현황 관리에 필요한 필수 데이터로 저장한다.
지원 기록을 만들 때 기본값을 제공해 별도의 선택 없이도 빠르게 저장할 수 있어야 한다.

지원 상태는 현재 단계와 전체 결과를 분리해 관리한다.

- 현재 단계: 서류, 테스트/과제, 면접, 처우 협의
- 전체 결과: 진행 중, 최종 합격, 입사 확정, 불합격, 종료
- 종료 사유: 지원 철회, 응답 없음, 채용 취소, 기타
- 기본값: 현재 단계 `서류`, 전체 결과 `진행 중`
- 최초 전형 이벤트: `지원 완료`
- 기본 화면 표시: `지원 완료`

화면에서는 값을 조합해 `면접 진행 중`, `면접 불합격`, `서류 단계에서 응답 없음`처럼
하나의 상태로 보여준다.
불합격이나 종료가 발생하면 당시의 현재 단계를 함께 보존해 단계별 통계에 활용한다.

진행 중인 지원에 30일 동안 새로운 기록이 없으면 `응답 없음` 종료를 제안하되
사용자의 확인 없이 자동으로 종료하지 않는다.
응답 없음 처리 후 늦게 결과가 도착하면 지원 기록을 다시 열고 상태를 변경할 수 있다.

#### 변경 이력과 되돌리기

- 지원 상태를 변경할 때 기존 이력을 덮어쓰지 않고 새로운 변경 이벤트를 추가한다.
- 변경 시각, 이전 값, 변경된 값과 변경 주체를 기록한다.
- 변경 주체는 사용자, 이메일 자동화 및 시스템으로 구분한다.
- 자동 변경과 수동 상태 변경은 타임라인에서 되돌릴 수 있어야 한다.
- 되돌리기도 새로운 변경 이벤트로 기록해 이력을 보존한다.
- 메일 본문 등 변경 확인에 불필요한 민감정보는 이력에 저장하지 않는다.
- 영구 삭제는 되돌릴 수 없으므로 삭제 범위를 안내하고 별도 확인을 받는다.

#### 일정과 다음 할 일

하나의 지원 기록에 여러 일정과 할 일을 등록할 수 있다.

- 종류: 서류 마감, 테스트 기한, 과제 제출, 면접, 결과 발표, 후속 연락, 기타
- 입력 정보: 제목, 종류, 필수 날짜, 선택 시간, 시간대, 완료 여부, 메모
- 가장 가까운 미완료 항목을 해당 지원의 `다음 할 일`로 표시
- 기한이 지난 미완료 항목은 기한 초과로 표시

시간을 모르는 일정도 등록할 수 있도록 날짜만 필수로 한다.
시간을 입력한 경우 해당 지역의 정확한 시각이 지난 뒤 기한 초과로 처리하고,
시간이 없으면 저장된 시간대에서 해당 날짜가 끝난 뒤 기한 초과로 처리한다.
일정에는 생성 당시의 IANA 시간대를 보존해 프로필 시간대 변경으로 기존 시각이 바뀌지 않게 한다.

MVP에서는 일정 등록, 완료 처리, 기한 초과 표시와 대시보드 예정 일정 조회를 제공한다.
이메일 일정 자동 등록, 외부 캘린더 연동 및 별도 알림 발송은 후속 단계에서 개발한다.

지원 전 채용공고는 지원 기록에 포함하지 않고 추후 관심 공고 기능으로 분리한다.
관심 공고는 총 지원 건수와 합격률 계산에서 제외한다.

### C. 취업 활동 분석

- 총 지원 건수
- 진행 중인 지원 건수
- 서류 합격률
- 면접 합격률
- 전체 지원 기준 단계 전환율
- 미응답률
- 이력서 버전별 지원 결과
- 기간별 지원 추이
- 기업 유형별 지원 결과

확정 합격률은 명시적인 합격과 불합격만을 대상으로 계산한다.

`확정 합격률 = 합격 수 / (합격 수 + 명시적 불합격 수)`

전체 지원 기준 단계 전환율은 응답 없음도 실질적 실패로 포함한다.

`전체 지원 전환율 = 다음 단계 진입 수 / (다음 단계 진입 수 + 불합격 수 + 응답 없음 수)`

진행 중, 지원 철회 및 채용 취소는 두 계산의 분모에서 제외한다.
응답 없음은 불합격과 별도로 저장하고 미응답률로 함께 보여준다.

서로 다른 기업이나 직무에 지원한 결과를 비교할 때
이력서 변경만이 성과 차이를 만들었다고 단정하지 않는다.

#### AI 취업 활동 인사이트

충분한 지원 기록이 쌓이면 통계와 제출 문서별 결과를 바탕으로
사용자가 자신의 취업 활동을 해석할 수 있도록 AI 인사이트를 제공한다.

- 상대적으로 결과가 좋은 지원 단계, 직무, 지원 경로 및 문서 버전 요약
- 개선이 필요한 전형 단계와 반복되는 정체 구간 안내
- 사용자의 강점과 주의해서 해석해야 할 패턴 설명
- 다음 지원에서 확인하거나 개선할 수 있는 행동 제안

AI 인사이트에는 분석 기간, 표본 수와 근거가 된 지표를 함께 표시한다.
데이터가 부족하면 평가를 만들지 않고 부족한 데이터와 그 이유를 안내한다.
문서 버전별 결과 차이는 상관관계로만 설명하며 특정 이력서가 결과의 원인이라고
단정하지 않는다. 이력서나 자기소개서 본문을 분석할 때는 별도 동의를 받고
분석 목적과 데이터 처리 방식을 명확히 안내한다.

기본 통계 계산은 AI에 의존하지 않고 동일한 규칙으로 재현 가능해야 한다.
AI 인사이트 생성은 MVP 이후 기능으로 개발한다.

### D. 연결 관계 시각화

- 이력서 및 자기소개서 버전과 지원 기록의 연결 표시
- 기업, 직무, 채용공고, 전형 단계 및 결과의 연결 표시
- 특정 문서 버전을 사용한 지원과 결과 탐색
- 특정 기업 또는 지원 기록을 중심으로 한 관계 보기
- 노드 선택 시 관련 기록과 상세 정보로 이동
- 직무, 기간, 상태 및 문서 버전에 따른 필터링

전체 관계 그래프는 충분한 데이터가 축적된 이후 가치를 내는 기능이므로
초기 MVP에서는 관계를 보존할 수 있는 데이터 구조와 단순한 요약 시각화를 우선한다.
인터랙티브 그래프의 구체적인 MVP 포함 범위는 별도로 결정한다.

개인 이력서와 지원 기록을 기반으로 한 시각화는 기본 비공개로 제공한다.

### E. AI 기업 및 채용공고 분석

- 채용공고 텍스트 분석
- 필수 역량 및 우대사항 추출
- 사용자 이력서와 요구사항 비교
- 경험과 역량의 연결점 분석
- 이력서 보완 방향 제안
- 예상 면접 질문 생성
- 기업 분석 및 출처 표시

면접 일정이 등록되거나 이메일 연동을 통해 감지되면
해당 지원 기록을 기반으로 면접 준비 자료를 자동 생성할 수 있다.

- 기업의 주요 사업, 제품 및 최근 확인 가능한 정보 요약
- 지원 직무와 채용공고의 핵심 요구사항 정리
- 제출한 이력서·자기소개서와 요구사항의 연결점 정리
- 사용자 경험을 바탕으로 답변을 준비할 항목 제안
- 직무 및 기업에 맞춘 예상 면접 질문 생성
- 면접일까지의 준비 체크리스트 제안

근거 없는 합격 확률을 생성하지 않는다.

AI 분석은 실제 채용공고와 확인 가능한 기업 정보를
기반으로 수행해야 한다.
외부 기업 정보에는 출처와 확인 날짜를 표시하며,
확인되지 않은 추측을 사실처럼 제공하지 않는다.

사용자의 이력서와 자기소개서를 AI 분석에 사용하는 경우 별도 동의를 받고,
분석 목적과 데이터 처리 방식을 명확히 안내한다.

### F. 취업 준비생 커뮤니티

- 익명 이력서 공유
- 다른 사용자의 공개 이력서 열람 및 참고
- 이력서 피드백
- 경험 있는 사용자 또는 경력자의 이력서 첨삭
- 포트폴리오 공유
- 취업 경험 공유
- 직군별 게시판
- 댓글 및 피드백

커뮤니티는 초기 MVP 이후에 구현한다.

사용자의 원본 이력서와 지원 기록은 기본 비공개다.
커뮤니티에 공개하거나 특정 사용자에게 공유할 때는 공개할 문서 버전과 허용 동작을
사용자가 직접 선택해야 한다.

### G. 이메일 연동 및 전형 상태 자동화

- Gmail 및 Outlook 등 사용자가 허용한 메일 계정 연동
- 새로운 채용 관련 메일 감지
- 메일 내용에서 기업, 지원 직무, 전형 단계 및 결과 추출
- 기존 지원 기록과 자동 매칭
- 전형 상태 변경 및 전형 이력 자동 추가
- 면접 일정 감지 시 AI 면접 준비 자료 생성 연결
- 사용자가 자동 반영에 동의하지 않았거나 매칭이 불확실한 경우 변경 제안

사용자가 명시적으로 동의한 경우에만 메일 분석 결과를 자동 반영한다.
기업과 지원 기록, 전형 결과를 신뢰도 높게 식별한 경우에만 자동 처리하며,
모호하거나 충돌하는 결과는 사용자에게 확인을 요청한다.

자동 변경 시 어떤 메일을 근거로 무엇이 바뀌었는지 알리고,
사용자가 변경을 즉시 되돌릴 수 있어야 한다.

필요한 최소 권한만 요청하고, 분석에 불필요한 메일과 본문은 저장하지 않는 것을 원칙으로 한다.
사용자는 언제든지 메일 연동을 해제하고 관련 데이터를 삭제할 수 있어야 한다.

## 5. MVP 범위

첫 번째 출시에서 구현할 핵심 기능은 다음과 같다.

1. Google·Kakao 소셜 로그인
2. 10MB 이하 PDF 이력서·자기소개서 업로드
3. 이력서 버전 관리
4. 버전별 변경 내용 기록
5. 자기소개서 파일 업로드 및 버전 관리
6. 기업 및 지원 기록 등록
7. 채용 전형 상태 관리
8. 전형 상태 변경 이력 및 되돌리기
9. 이력서·자기소개서 버전과 지원 기록 연결
10. 지원별 일정과 다음 할 일 관리
11. 지원 현황 및 예정 일정 대시보드
12. 기본 합격률 통계

선택한 두 PDF 버전을 나란히 보는 기능은 MVP 권장(Should) 항목이며,
핵심 출시를 막는 필수(Must) 항목으로 취급하지 않는다.

AI 취업 활동 인사이트, AI 기업 분석, 커뮤니티 및 이메일 연동은 후속 단계에서 개발한다.
자기소개서 직접 작성, 문항별 답변 재사용 및 편집 기능도 후속 단계에서 개발한다.
PDF 텍스트 자동 추출, Git 스타일 자동 비교 및 AI 변경 요약도 후속 단계에서 개발한다.
지원 기록 CSV와 원본 PDF를 포함한 전체 데이터 내보내기도 후속 단계에서 개발한다.

데이터 내보내기는 MVP에서 제공하지 않지만,
사용자별 데이터 소유 관계와 구조화된 기록을 유지해 추후 내보내기가 가능하도록 설계한다.

이 범위와 `docs/PRD.md`를 초기 구현 기준으로 사용하며,
범위가 변경되면 관련 문서와 의사결정 기록을 함께 갱신한다.

### MVP 인증 범위

- Supabase Auth 기반 소셜 로그인만 제공한다.
- Google과 Kakao 로그인을 우선 제공한다.
- 이메일·비밀번호 및 매직 링크 로그인은 제공하지 않는다.
- Naver 로그인은 MVP 이후 Custom OAuth 호환성을 검증한 뒤 추가한다.
- 로그인 권한과 Gmail 채용 메일 분석 권한은 분리해 요청한다.

## 6. 사용자 흐름

1. 사용자가 회원가입한다.
2. 기존 이력서와 자기소개서 파일 및 버전을 등록하거나, 이 단계를 건너뛴다.
3. 지원할 기업과 직무, 채용공고를 등록한다.
4. 등록된 이력서나 자기소개서가 있다면 지원 당시 사용한 버전을 선택하거나, 연결 없이 지원 기록을 저장한다.
5. 필요한 경우 나중에 지원 기록에 제출 문서 버전을 추가한다.
6. 채용 절차가 진행되면 상태를 변경한다.
7. 결과가 누적되면 대시보드에서 통계를 확인한다.
8. 추후 AI 분석, 커뮤니티 및 이메일 연동을 이용한다.

## 7. 디자인 방향

- 친근하고 귀여운 브랜드 이미지
- 깔끔하고 직관적인 UI
- 토스처럼 이해하기 쉬운 사용자 경험 지향
- 모바일과 데스크톱 모두 대응
- 대시보드와 기록 관리에 최적화
- 불필요하게 복잡한 입력 과정 최소화
- 화이트 배경을 기본으로 사용
- 연한 연두색 `#9DDF50`을 브랜드 중심 색상으로 사용
- 미국 도로와 도로 표지판을 연상시키는 브랜드 심볼 사용
- Tailwind CSS의 의미 기반 변수를 사용해 테마 확장이 가능한 구조로 구현

브랜드명은 MILO로 확정했다.

MVP는 라이트 테마만 제공하며 다크 모드는 후속 단계에서 확장한다.
초기 로고는 연두색 도로 방패 안에 굵은 `M`을 넣은 단순한 심볼을 사용하며,
향후 브랜드 개선 과정에서 교체할 수 있다.
마스코트와 세부 컴포넌트 디자인은 사용자 검토 후 확정한다.

## 8. 기술 스택

### 확정

- Next.js App Router 기반 풀스택 구성
- TypeScript (strict)
- Node.js 런타임
- Supabase PostgreSQL
- Supabase Auth
- Supabase Storage
- Drizzle ORM 및 Drizzle Kit
- Tailwind CSS
- shadcn/ui

MVP에서는 별도의 Express 또는 NestJS 백엔드 서버를 두지 않는다.
AI 분석, 이메일 처리 및 OCR처럼 장시간 비동기 작업이 필요해지면
별도 Node.js Worker와 작업 큐 도입을 검토한다.

### 후보 또는 필요 시 도입

- TanStack Query
- Zustand
- Recharts

나머지 기술 스택은 실제 요구사항에 맞춰 순차적으로 선택한다.

## 9. 초기 사용자 확보 전략

- 개발자 취업 준비생을 초기 사용자군 중 하나로 고려하되, 서비스 이용 대상을 개발 직군으로 제한하지 않는다.
- 신입과 경력직 모두 기존 이력서와 지원 내역을 관리할 수 있게 한다.
- 기존 이력서 PDF를 바로 등록할 수 있게 한다.
- 복잡한 초기 설정 없이 지원 내역을 기록할 수 있게 한다.
- 사용자 피드백을 받아 기능을 개선한다.
- 커뮤니티는 개인 기능에 사용자가 확보된 후 확장한다.

## 12. 개발 목표

첫 번째 목표는 기능이 많은 서비스를 만드는 것이 아니다.

사용자가 실제로 이력서를 등록하고,
기업별 지원 내역을 기록하며,
그 기록을 다시 확인하고 싶어지는
작동 가능한 웹서비스를 출시하는 것이다.

## 13. 엔지니어링 및 포트폴리오 목표

MILO는 실제 사용자의 문제를 해결하는 서비스인 동시에 기술적 선택과 개선 과정을
검증하고 설명할 수 있는 포트폴리오 프로젝트로 개발한다.

- GitHub Actions를 활용해 타입 검사, 린트, 테스트와 빌드 검증을 자동화한다.
- 테스트, 보안, 관측 가능성, 배포 자동화와 AI를 실제 문제를 해결하는 범위에서 적용한다.
- 중요한 기술 선택은 문제, 대안, 선택 근거, 트레이드오프와 결과를 문서로 남긴다.
- 실험적인 기술은 핵심 사용자 흐름을 해치지 않도록 작은 단위로 도입하고 검증한다.
- 사용 기술의 개수보다 사용자 가치, 운영 안정성과 측정 가능한 개선 결과를 우선한다.

기술 실험은 제품의 목적이 아니라 제품을 더 안전하고 편리하게 만드는 수단으로 다룬다.
