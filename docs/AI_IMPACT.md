# AI 활용 및 개선 기록

MILO에서 AI를 활용한 작업과 그 효과를 검증 가능한 형태로 기록한다. 이 문서의 목적은
AI를 사용했다는 사실을 나열하는 것이 아니라, 어떤 문제를 어떻게 개선했고 그 결과를
어떤 근거로 확인했는지 설명하는 것이다.

## 기록 원칙

- AI 적용 전에 가능한 경우 기준선(`before`)을 먼저 측정한다.
- 시간, 정확도, 실패율, 비용처럼 비교 가능한 지표를 사용한다.
- 측정할 수 없는 효과는 숫자로 만들어내지 않고 정성 결과로 구분한다.
- 코드 줄 수, 생성한 파일 수와 프롬프트 수는 개선 효과의 핵심 지표로 사용하지 않는다.
- AI가 제안하거나 생성한 결과는 사람이 검토하고 테스트한 범위를 함께 기록한다.
- 이력서, 자기소개서, 이메일 본문과 비밀키 등 민감정보를 프롬프트나 공개 기록에 남기지 않는다.
- 사용자 대상 AI 기능은 오탐, 누락, 근거 표시, 처리 시간과 비용을 함께 평가한다.

## 측정 대상

### 개발 과정

| 목표 | 우선 지표 | 보조 근거 |
| --- | --- | --- |
| 반복 작업 자동화 | 수동 단계 수, 작업 시간, 실패율 | 워크플로 실행 기록 |
| 구현 속도 개선 | 동일 범위 완료 시간 | 작업 로그, 커밋과 PR |
| 코드 품질 개선 | 배포 전 발견 오류 수, 회귀 오류 수 | CI, 테스트 결과 |
| 문서화 개선 | 누락된 결정 수, 검토 소요 시간 | ADR, 변경 이력 |

### 사용자 대상 AI 기능

| 기능 | 우선 지표 | 반드시 확인할 위험 |
| --- | --- | --- |
| 채용 메일 분류 | 정밀도, 재현율, 자동 반영 승인률 | 잘못된 상태 변경 |
| 기업·공고 분석 | 근거가 있는 항목 비율, 사용자 채택률 | 사실 오류와 오래된 정보 |
| 면접 준비 자료 | 유용하다고 평가한 항목 비율, 준비 시간 | 일반적이거나 근거 없는 질문 |
| 취업 활동 인사이트 | 근거 지표 일치율, 제안 채택률 | 적은 표본의 과도한 일반화 |

## 작업별 기록 형식

각 실험이나 자동화가 완료될 때 아래 항목을 복사해 기록한다.

```md
### YYYY-MM-DD — 작업명

- 문제:
- AI 활용 범위:
- 사람이 판단하거나 수정한 부분:
- 기준선:
- 변경 후 결과:
- 개선율 또는 차이:
- 측정 방법과 표본:
- 검증 근거:
- 한계와 다음 실험:
```

개선율은 같은 조건에서 비교할 수 있을 때만 다음 식으로 계산한다.

```text
시간·오류처럼 낮을수록 좋은 지표 개선율 = (기준선 - 변경 후) / 기준선 × 100
정확도처럼 높을수록 좋은 지표 차이 = 변경 후 - 기준선
```

## 현재 기준선

### 2026-10-26 — CI 도입 전

- 문제: 변경 후 품질 검사를 개발자가 로컬에서 명령별로 직접 실행해야 한다.
- 수동 검증 단계: `lint`, `typecheck`, `build`의 3단계
- 자동 검증: 없음
- 변경 후 측정 항목: GitHub Actions 성공률, 평균 실행 시간, 배포 전 발견 오류 수
- 비고: 실행 시간이 아직 수집되지 않았으므로 개선율은 첫 CI 실행 이후 기록한다.

## 공개 포트폴리오 작성 기준

포트폴리오에는 도구 이름보다 문제와 결과를 먼저 적는다.

> PR마다 린트·타입 검사·프로덕션 빌드를 자동 실행해 3개의 수동 검증 단계를 제거하고,
> 실패한 변경이 운영 브랜치에 반영되기 전에 확인할 수 있도록 구성했다.

위 문장의 실행 시간이나 오류 감소율은 실제 GitHub Actions와 장애 기록이 쌓인 뒤
측정값으로 보완한다. 측정하지 않은 생산성 향상이나 품질 향상을 임의의 백분율로 표현하지 않는다.
